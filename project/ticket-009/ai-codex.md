# Participant: codex (AI agent)

## Understanding

The user wants Subactor to behave like an evolutionary organism: a durable
purpose and current context should condition the next process in the way a
language model conditions the next token. The safe equivalent is not free-form
URI generation. It is an accepted purpose DSL plus Digital Twin evidence,
deterministic candidate selection, catalog binding, authority, execution and an
independent receipt that becomes context for the next decision.

## Execution plan

1. Preserve the existing authority and controller boundaries.
2. Define strict purpose and process-token contracts.
3. Add deterministic, hash-chained next-process projection and CLI streaming.
4. Demonstrate the organism lifecycle with a Subactor purpose example.
5. Test determinism, human interaction, waiting and fail-closed validation.

## Actual changes

- Initialized the bounded ticket and recorded SESSION_EXECUTION_AUTHORIZATION
  from the request to execute this work.
- Audited the ecosystem with Diagit, Todocs, the internal knowledge base and a
  live/offline Twin projection before choosing the implementation owner.
- Selected `twin-subactor` for prediction only; Control/Autonom remain the
  runtime owners of scheduling, binding, grants, execution and rollback.
- Added strict purpose and process-token contracts, deterministic selection,
